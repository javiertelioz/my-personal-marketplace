# Start here

Use this file first to decide which reference to open next.

## If the task is...

| Task | Read next |
|---|---|
| Create a brand new skill | `skill-specification.md` and `writing-a-good-skill.md` |
| Fix frontmatter or directory problems | `skill-specification.md` |
| Improve triggering and activation | `writing-a-good-description.md` |
| Decide whether to add scripts | `using-scripts.md` |
| Validate a finished skill | `validating-a-skill.md` |
| Add eval files and assertions | `evaluating-a-skill.md` |
| Perform a final audit | `checklist.md` |

## Recommended authoring order

1. Define the skill name and user intent.
2. Read `skill-specification.md`.
3. Draft `SKILL.md` with help from `writing-a-good-skill.md`.
4. Improve the frontmatter description with `writing-a-good-description.md`.
5. Add `references/`, `scripts/`, and `assets/` only when they add clear value.
6. Validate with `validating-a-skill.md`.
7. Scaffold and customize evals with `evaluating-a-skill.md`.
8. Run the final pass against `checklist.md`.

## Practical rule

Do not read every reference up front.

Read only the file that answers the current question, then return to the main workflow.
